# Feature-to-job-duty mapping

The duty descriptions below are paraphrased general SDS-coordination tasks,
based on the project specification's summary of the posting (SDS revision
coordination). Check the wording against the actual posting before using it
in an application. This project is an independent work sample and is not
affiliated with or endorsed by Techmer PM.

| Job-related duty (paraphrased) | Feature in this project | What it shows |
|---|---|---|
| Receive and keep supplier SDS documents on file | Receipt record for every upload, hash-based storage, originals never overwritten | Accurate document records |
| Tie each SDS to the right raw material | Candidate suggestions plus required human confirmation; CAS not used as identity | Care with identity; no silent linking |
| Spot when a supplier has issued a revised SDS | Classification against an explicit baseline with a stated reason | Revision recognition with traceable reasoning |
| Notice missing or inconsistent information | Field statuses (found, missing, ambiguous, conflicting) with evidence; manual-review outcome | Recognition of missing or conflicting information |
| Identify what changed in hazard-relevant content | Section 2/3/8/14/15 text comparison with explicit statuses | Revision comparison with stated scope |
| Route changes to regulatory staff for review | Notification draft (not sent) and review acknowledgment | Clear handoff; no automated regulatory decisions |
| Keep a record of what was done and when | Activity history timeline | Traceable activity history |
| Be candid about what a tool can and can't do | Persistent notice, limitations in drafts, results/limitations report | Honest limits on automation |
